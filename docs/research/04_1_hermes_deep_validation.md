# Task 4.1 · Hermes 자율 연구와 장기 기억 재검증

2026-11-12 KST · [Task 4](04_final_architecture.md) 후속

## 핵심 결론

**기본 아키텍처는 B를 유지하되, 다음 실험은 C를 실제로 가동하는 격리 연구 Shadow로 바꾼다.** A(현행)·B(얇은 설계 차용)·C(실제 Hermes)를 같은 데이터와 예산으로 비교한다. C가 이기면 연구 과제의 스케줄링·위임·재개를 Hermes에 맡길 수 있다. 첫 시험부터 Hermes 기능을 자체 재구현할 필요는 없다.

결정의 근거는 다음 세 가지다.

1. Hermes에는 대화 기록을 넘어 **작업 재개에 필요한 상태, 실패별 재시도 분류, 완료 통지의 복원**이 있다. 여러 분기에 걸친 가설의 후속 조사와 사람 개입 감소에 검증할 가치가 있다. 다만 작업 소유자가 사라진 경우 외부 효과는 상태 불명일 수 있다.
2. **능동적 투자 기회 발굴과 전략 학습은 아직 입증되지 않았다.** 이벤트의 중요도, 기업·공급망 연결, 반례에 따른 후속 조사, 검증 과제 등록 및 중단은 별도 연구 계약이 필요하다. Hermes는 이를 조율할 수 있고, 실험·승격의 권위는 Factory가 갖는다.
3. 이번에는 Hermes 고정 소스의 재개 분류 5개, 원본 메모리·읽기 전용 세션 검색 테스트 6개, 원본 위임 재개·claim 테스트 18개를 통과했다. 전체 Cron/Gateway의 강제 종료 복구, 장기 기억의 정확도, 분석·수익 개선은 아래 비교 실험의 대상이다. 운영 코드와 전략 변경은 없다.

**최소 구성**은 공식 공시·IR 수집과 시점 저장 → Task 3 조사 및 조건부 예측 → Hermes 또는 현행 작업 조율 → 독립 복기 → Factory 검증이다. 거래·승인 경로는 별도로 둔다.

## 1. 실질적 증분 가치와 중복

| 능력 | Hermes가 제공하는 경계 | 투자 시스템에서 필요한 추가 기능 |
|---|---|---|
| 새 사건·반례에 반응 | Cron·Gateway로 작업을 열고, 모델이 도구와 자식 작업을 선택할 수 있다. | 공시 원문 관측 큐, 예상 밖 변화·기존 가설 충돌 판정, 중요도 평가, 기업·공급망 매핑과 만료 시각. 검색 계획은 Hermes/기존 분석가가 비교하고 사실 채택은 독립 검증기가 수행한다. |
| 조사 이어가기 | 세션 검색·lineage, 컨텍스트 압축, 중단된 자식 재구성에 필요한 기록. | 분기별 가설 상태·미해결 질문·예정 관측·원문 버전. 새 세션에서 ID로 공식 기록을 재조회하며 요약의 숫자·단위·만기를 대사한다. |
| 가설 재검토 | 자식 결과를 모아 재질문하고 후속 작업을 예약할 수 있다. | 반례와 정정 발생 시 가설의 버전을 추가하고, 유효기간 만료·폐기·보류를 명시한다. 중복은 세션 검색 결과가 아니라 Factory의 fingerprint와 의미 유사 후보 검토로 차단한다. |
| 분석 방법·전략 발전 | 스킬 작성·수정 및 재사용이 작업 절차의 개선을 지원한다. | 정보원·선행 지표가 실제 예측력을 높이는지는 고정 예산의 독립 실험. 매매 전략은 비용·위험 포함 replay 및 독립 Forward, 인간 승인으로 결정한다. |

현재 OpenDART/RSS Shadow는 관측과 후보 근거 기록의 시작점이며, Task 3의 `A0→A1→B1→B2→B3`는 데이터·스킬·반론·복기를 분리한다. Hermes 평가에서는 그 연구 프롬프트를 고정하고 **조율기만 교체**한다. Task 3의 정보 효과와 Task 4.1의 런타임 효과를 한 실험에서 섞지 않는다. [기존 조사](01_github_discovery.md) · [도구 비교](02_repository_comparison.md) · [실패 보완](02_validation_addendum.md) · [Task 3](03_investment_skills.md)

중복 지점은 예약기, 복기 체크포인트, 모델 호출 기록, 자식 상태의 권위다. 한 연구 경로에는 Hermes나 현행 작업 관리기 중 하나만 쓰고, LangGraph는 이미 검증한 복기 단계에만 둔다. TradingAgents의 성숙 결과 주입은 금융 평가에 특화돼 있고 RD-Agent의 생성→코딩→평가→trace는 연구 탐색에 특화돼 있다. Hermes의 강점은 이 작업 사이의 탐색·호출·맥락 복원이다. 한 기능을 두 런타임에서 실행하는 상시 중복은 비용만 늘린다.

## 2. 자율 연구와 자기개선의 경계

**연구 시작·확장·중단.** 공식 이벤트가 들어오면 source ID와 관측 시각으로 중복을 제거하고, 기존 thesis와 충돌하는지 비교한다. 새로운 계약이면 금액·구속력·인식 조건을 확인하고, 산업 변화면 관련 고객·경쟁사·공급망까지 1단계 확장한다. 확장 제안은 현재 가설을 바꿀 가능성, 원천 신뢰도, 기한, 추가 검색 비용 순으로 평가한다. 증거가 같은 출처를 반복하거나 가설을 바꿀 가능성이 낮으면 중단한다. 관측이 더 필요하면 질문·필요 원문·만기·다음 체크 날짜를 남긴다.

첫 회차의 **제안 상한**은 사건당 자식 2개, 확장 깊이 1, 외부 자료 조회 12회, 총 12,000 모델 토큰, 15분, 일일 사건 4건이다. 비교 전 고정하고 압축·요약·재시도·중단 작업도 같은 예산에 넣는다. 소스 확인과 중복 제거는 코드, 선행 지표·반증 추론에는 모델을 쓴다. 에이전트가 자체적으로 한도를 늘릴 권한은 없다. 새 실험은 기존 Factory의 회차당 최대 3개와 운영 replay 최대 1회를 따른다.

| 개선 수준 | 변경 후보 | 승인에 필요한 증거 |
|---|---|---|
| 작업 효율 | Hermes의 검색·도구 순서·요약·스킬 | 같은 근거 회수와 과제 완결률에서 개입·토큰·시간 감소. 버전 비교 후 연구 스킬에만 반영 |
| 분석 능력 | 새로운 공시 채널, 수주→매출 전달 변수, 신규 선행지표 | 독립 원문 확인 및 같은 증거·예산 대비 예측 개선. 누락·오탐과 정보 수집 비용 포함 |
| 전략 개선 | 선정·진입·비중·청산 규칙 | Factory 사전등록, 격리 실행, 비용 후 독립 평가, Forward 증거, 승인. Hermes가 전략 파일·운영 계정에 쓸 수 없음 |

**실패→원인 가설→방법 제안→격리 실험→독립 평가**를 각각 기록한다. 먼저 당시 입력만으로 과정 평가를 봉인하고, 그 다음 실제 결과를 공개해 시장 충격·가설 오류·실행 문제를 나눈다. 실패·기권·중단도 남긴다. 성공 사례에서만 교훈을 학습시키지 않고, 무관한 복기를 섞은 대조군과 반사실적 무거래/동일 위험 대안도 기록한다. 최종 평가 기간은 RD-Agent·Hermes의 다음 가설 생성 입력에서 가린다.

## 3. 기억 권위와 재개 상태

| 계층 | 내용과 권한 |
|---|---|
| 자연어 메모리 | 작업 방식, 현재 문맥, 가설 ID, 과제 포인터. 세션 압축·수정 가능. 장기 기억은 편의 계층으로 사용하고 원문·시장 기대의 증명에는 사용하지 않는다. |
| 구조화된 투자 연구 기록 | 가설 ID·버전·상태·근거 hash·available_at·반례·1/2/4분기 예측·관측 기한·실패·실험 결과. 정정과 폐기는 append. 프롬프트가 제안한 내용과 승인 상태를 별도 필드로 관리한다. |
| 변경 불가능한 거래·평가 원장 | 당시 정보·전략/입력 hash·판단·주문·체결·비용·성과. 독립 서비스만 append하며 연구자는 마스킹된 읽기 권한만 갖는다. |

과거 자료가 세션 시작 시각보다 나중에 추가됐을 수 있으므로, 검색 결과마다 연구 레코드와 원문의 이용 가능 시각을 재검사한다. 상충·정정된 숫자는 최신 문장으로 덮어쓰지 않고 유효기간을 붙인다. 첫 독립 분석은 다른 분석가의 결론·기억 검색을 차단하고, 봉인 후 공유할 때에도 원문 출처와 결론을 구분한다. 프로필 분리는 운영 편의이며 실제 접근 격리는 별도 파일·도구·데이터 권한으로 구현한다.

재개에서 신뢰할 키는 `task_id + attempt_id + contract/input_hash`와 외부 호출·결과 저장 영수증이다. 완료 후 알림 미전달은 재전달, 실행 중 소유자 유실은 상태 조회와 대사, 증거 없는 외부 효과는 사람 확인 또는 읽기 전용 재실행으로 구분한다. Factory의 현재 budget read→append는 병렬 호출 이전에 단일 등록자 또는 원자적 예약으로 보호할 필요가 있다. 재개가 반복 실험이나 주문 재발행으로 이어질 권한은 없다.

## 4. A·B·C·D의 경제성

| 대안 | 증분 가치와 중복 | 채택 조건 |
|---|---|---|
| A 현행 개선 | 의존성과 권한 표면이 작다. 기존 Factory와 체크포인트를 활용한다. 작업 검색·재개·위임 추적을 직접 관리해야 한다. | 연구량이 작고 C/B의 개선폭이 운영비를 넘지 않을 때 |
| B 일부 설계 차용 | 과제 포인터와 시점 필터, 구조화 상태의 장점을 작은 변경으로 확인. Hermes 전체 기능을 직접 구현하면 Gateway·재개·이벤트 전송 유지비가 커진다. | 단일 작업 큐와 제한적 검색만으로 목표를 충족할 때 |
| C 지속형 연구 총괄 | 실제 세션 검색·역할별 위임·실패 상태·예약을 재사용할 수 있다. DB·프로필·Gateway 운영, 권한 설계, 모델 호출·압축 비용이 추가된다. | 동일 예산에서 A/B보다 완결률·회수·개입 비용 개선을 입증할 때. 연구 런타임만 교체 |
| D 특정 에이전트 교체 | 효과가 약한 한 기능(예: 수동 후속 조사나 알림)을 줄일 수 있다. 상태 이전과 기존 프롬프트 재검증이 필요하다. | C를 통과한 후 해당 기능을 껐을 때도 품질과 재현성 유지가 확인될 때 |

**경제성은 직접 측정한다.** 동일 사례에서 운영 개입 분·장애 복구 시간·완료 건당 총 모델/도구 비용과 구현·업데이트 시간을 기록한다. 연간 비용에는 셋업·유지·장애 대응 시간을 포함한다. 큰 프로토타입부터 만들면 B의 비용을 과대 평가하므로 B는 연구 ID 조회와 얇은 작업 상태만 구현하는 대조군으로 정의한다.

## 5. 세 시나리오의 비교 계약

A는 현행 연구 경로, B는 얇은 검색·후속 작업 상태, C는 격리 Hermes 런타임이다. A도 공통 원문·검색 도구와 동일 모델·예산을 받는다. 초기에 같은 입력을 준 뒤 다른 후보 결과는 가리고, 무작위 실행 순서와 독립 채점을 적용한다. 다음은 사전등록할 **제안 기준**이다. 수치는 실제 통과 결과가 아니다.

| 시나리오 | 현재 확인 범위 | 다음 최소 실행과 성공 기준 |
|---|---|---|
| A 새로운 기회 | 작업을 예약·위임할 코드 확인. 시장 기회 발굴 비교 미실행 | KRX·미장 공식 사건의 시점별 고정 자료에서 기존 관측 외 기업을 찾는 12개 짝지은 사례. 충돌·노이즈도 포함. 검증 가능한 신규 근거/호출, 오탐, 독립 원문 2개 확인 또는 단일 공식 근거, 인과 가설과 다음 관측을 채점. C의 신규 유효 근거 또는 완결률이 B보다 개선되고 오탐률이 늘지 않아야 확대. |
| B 장기 연구 재개 | 원본 메모리·검색·위임 테스트 확인. 여러 분기 기억 회수·실행 중 실제 프로세스 강제 종료 미실행 | 3개 분기의 가설·정정·반례·미완료 상태를 고정하고 12개 과제를 새 프로세스로 재개. 완료 전 강제 종료, 완료 후 통지 전 종료, 검색 후보에 미래 수정본 삽입을 각각 시험. 공식 ID/버전·숫자·보류 상태 정확 ≥95%, 미래 노출·중복 결과/효과 0. 정확도가 같으면 C의 사람 개입 또는 완료당 비용 20% 이상 절감을 확장 기준으로 제안. |
| C 실패 후 개선 | Hermes 스킬 변경 경로 및 RD-Agent trace 구조 확인. 실제 원인→격리 평가 순환은 미실행 | 실패·성공·기권을 균형 있게 제시하고 과정 채점을 먼저 봉인. 같은 예산에서 고유한 원인 가설·신규 정보원과 반증을 작성해 Factory에 등록. 성공률은 독립 검토를 통과한 새 검증 가능 가설과 완료 실험으로 집계. 결과 셔플 placebo가 같은 개선을 내거나 holdout 누출·반복/무승인 등록이 발생하면 중단. |

절대 중단 조건은 원문 이용 가능 시각 위반, 접근 범위 외 쓰기, 예산 초과, 중복 외부 효과, 거래 권한 노출이다. 소표본은 운영·채점 점검용이며 초과수익 승격 근거로 쓰지 않는다. 이후에는 Task 3 방식으로 동일 원문에서 1·2·4분기 예측 오차와 당시 시장 기대 비교를 채점하고, 독립 Forward에서 비용 차감 초과수익과 위험을 별도 측정한다. 운영 효율 우위가 있으면 연구 총괄로 사용할 수 있으며 투자 판단 권한은 별도 효능 증거가 필요하다.

## 6. Task 4에서 바꿀 결정

1. 기존 **B 선행 구축**을 **A/B/C 공통 fixture와 C 읽기 전용 시험**으로 바꾼다. 작업자에게 시장 원문과 가설 조회·후속 과제 제안만 열고 계좌·브로커·전략 코드 쓰기 권한은 분리한다.
2. 재개 기록은 단순 완료 통지와 분리한다. `unknown` 상태, 가짜 외부 호출, 영수증 대조를 C의 우선 장애 시험에 추가한다.
3. 스킬의 자동 생성 결과는 별도 실험 대상으로 취급한다. 동결 버전, 외부 접근 제한과 샌드박스를 요구하고, Factory에 제안하는 권한과 독립 평가·승인 권한을 분리한다.
4. C가 연구 비용·연속성의 우위를 보이면 연구 전용 총괄로 전환한다. D는 한 기능씩 제거 실험하고, 실제 거래·승격은 현재 결정론적 경계에 둔다.

## 부록 · 검토 코드와 실측 범위

### 후속 실행 · 실제 두 프로세스 비교

**추가 강제 종료 시험.** [실행기](../../runtime/hermes_research_shadow/run_crash_probe.py)로 완료·호출 제한·실행 중의 합성 연구 과제 3개를 만들고, 실행 중 과제가 모의 외부 영수증을 저장한 직후 작업 프로세스를 강제 종료했다. 새 프로세스에서 Hermes 원본 `recover_abandoned_delegations`를 호출하자 완료 건은 완료로 남고, 호출 제한 건과 실행 중이던 건은 각각 재개 가능으로 남거나 전환됐다. 실행 중 건의 재개 분류는 `AUTO_ON_BOOT`였으며 자동 스케줄러 대신 명시적 continue를 호출했다. 미완료 2건만 후속 처리했고, 세 과제 모두 원문을 그대로 복원했다. 기존 모의 영수증 1개를 재사용했고 재개 중 외부 호출은 0건이었다. 모의 효과를 다시 수행하는 도구가 비활성화된 시험이므로, 실제 도구의 멱등성을 입증하지 않는다.

B안 JSON에서도 과제 원문 3/3과 동일 영수증을 읽었다. B는 로딩만, C는 상태 회수와 후속 실행까지 측정해 소요시간(약 2ms / 2.79초)을 직접 비교할 수 없다. 처음에는 upstream 모의 모델을 작업마다 재생성하며 테스트 세션 ID가 충돌했다. 하네스에서 고유 세션 ID를 주고 격리를 검사한 재실행은 종료 코드 0이었다. 종합 판정은 **B 기본 설계, C 연구 Shadow 후보 유지**다. C의 강제 종료 후 작업 상태 회수는 확인했으며, 동일 후속 업무까지 구현한 B와의 개입량·완료 비용 및 자동 Gateway 재개는 미검증이다.

고정 클론의 실제 `delegate_task`·SessionDB·배경 디스패치를 실행했다. 합성 기업의 가설 ID/버전, 수주잔고 1억 2천만 달러, 미해결 검수일을 입력했다. 모델은 원본 테스트의 scripted fixture를 사용했고 가격·뉴스·외부 모델·거래 도구는 호출하지 않았다. 첫 프로세스 PID 25612에서 호출 제한을 주입하자 자식은 `resumable/AUTO_AT`으로 저장됐다. 프로세스가 종료된 뒤 PID 22508에서 같은 임시 DB로 명시적 continue를 실행해 같은 자식 ID와 입력 원문을 복원하고 후속 처리 1회로 completed에 도달했다. B의 단순 JSON 기록도 동일 원문을 복원했다. 이 결과로 C의 재개 기능이 실행 가능함을 확인했다. B 대비 정확도 우위는 관측되지 않았으며, 자동 스케줄·강제 종료·중복 외부 효과·운영비는 미측정이다. 이번 Windows Python의 SQLite 3.45.1에 대해 Hermes가 WAL 대신 DELETE 모드를 사용했다고 경고했다. 동시 작업 시험에서는 실제 DB 모드와 버전을 기록한다.
